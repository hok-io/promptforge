# 現有功能用途測評協議

這是可重跑的本地合成情境，不冒充真實專案或人類時間實驗。測試集先於執行固定，8 條規則、6 張知識卡、14 個任務。Gold 是測評者對「完成這個任務需要甚麼」的判斷，沒有由工具輸出反推。

cases.json 指定應選規則與必要知識來源。規則 tests.change 只適用程式行為修改，API 規則只適用 API 行為變更；僅修改文件標點不需要這些約束。F13/F14 沒有部署知識卡，不能因此當成搜尋已滿足全部知識需求。

測量：漏選、誤選、完全符合 gold 的 frame、query top3 是否涵蓋所有指定來源、返回但不在指定來源內的項目、輸出字元及執行耗時。Gold 以外搜尋结果標記為「未指定」，不一律等於無用，需人讀後確認。

估計人工負擔只數「補一條／刪一條」的項目，不把它換算成時間。對照人手 baseline 是從同一組檔案挑出 gold 指令，不使用模型推測。比較工具減少複製的候選項與增加修正項，不能把項目數直接相減成時間收益。

人工 baseline 不計時，不宣稱人效率提升。搜尋只在一個小型合成資料集上測，無法推廣為真實檢索準確率。輸出字元不是模型 token；没有執行 agent，不評下游改碼品質。

執行前先重新 package JAR，避免使用過期程式。產物寫 build/usefulness-evaluation，不寫 fixture。每個 case 分開保存 stdout、stderr、exit code、耗時與計算欄位。所有指定来源必須存在；只允許 CLI 成功輸出作為品質計算。另檢查現有 conflicts 專案的 exit code 6，並記錄 validate 格式驗證。

這次先提交 fixtures 與預期，再提交 runner／結果解讀。這是測評資料，不是新增產品功能。
