# Web 工作台的實際用途

評估日期：2026-09-26。Git 展示日期依要求使用 9 月 17–24 日。這是功能及使用流程評估，不是有人類對照組的速度研究。

| 真實工作 | 以前要做甚麼 | 工作台提供甚麼 | 成功判準 |
|---|---|---|---|
| 準備付款修改任務 | 找規則、讀 ADR、整理來源，再複製成 prompt | 搜尋卡片、手動選規則、預覽有來源內容 | 任務、限制、ADR 正文與來源都可讀；錯選由人修正 |
| 重複使用同一任務格式 | 反覆複製模板和替換值 | 有序區塊、明確變數、保存與重載 | 下次只改任務或變數；原格式、選擇及次序保留 |
| 更新一個 skill | 改檔後難知道評估和批准屬於哪一版 | 原文＋references 的 hash、diff、評估、人的批准 | 改內容後舊批准失效；舊評估顯示過期；匯出不覆蓋 |

有價值的部分是減少反覆整理和找來源，並讓版本狀態看得見。第一次設定資料和第一次學習 UI 有成本；偶爾只寫一行任務時，CLI 可能更省步驟。尚未量測使用者完成時間，不能聲稱快了多少或省固定百分比 token。

核心自動匹配的既有固定案例仍只有 8/14 完全符合預期；Web 沒有改成語義理解。手動選擇能修正已知錯誤，但需要人的判斷。搜尋不會自動加入全部結果，選到的卡片才进入 prompt。

評估 JSON 可來自外部 agent，但此程式不呼叫 LLM。TEST 記錄只驗證既存文字證據和記錄 hash；不是重新執行評估裡聲稱的測試。MODEL_REVIEW 是意見，不能自動變成人的批准。

可驗證的使用證據放在 BrowserWorkflowTest、WebContractTest、PromptWorkflowTest 和 SkillWorkflowTest。瀏覽器測试會確認保存重載、Unicode、變數、區塊次序、過期版本及 skill 工作流程；API 和檔案測試覆蓋其他錯誤情況。最終執行結果另記 `web-verification.md`，沒有遠端 CI 執行就不宣稱遠端通過。
