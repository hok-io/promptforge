# 每個小功能怎樣完成

1. 寫 ADR：問題、決定、放棄甚麼、後果。
2. 先加測試；本機跑 `scripts/test.ps1`，記錄預期失敗（red）。
3. 只寫夠令這批測試通過的 Java 程式。
4. 再跑測試，並用一個真人任務手動檢查輸出。
5. 在 `docs/reviews/` 記錄 edge cases、實際用途是否相合、可讀性和遺留問題。
6. 一個小範圍 commit；保留 red/green Git 歷史供最後逐步 review。

每個大階段再做一次真實任務驗收。最初用「修改付款重試」、「更新 README」、「無關任務」三個例子，特別檢查是否亂加規則及是否把一句話變成長篇模板。
