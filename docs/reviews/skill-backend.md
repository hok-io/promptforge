# Skill backend implementation review

The workbench service keeps imported bundles inside the registered project, preserves the original `SKILL.md` text, and computes revisions from the UTF-8 bundle files while excluding its workflow metadata. Review, approval, activation, and export are tied to the current bundle revision. Evaluation records are immutable JSON sidecars; evidence paths are resolved through `WorkspaceFiles` and their contents are hashed when recorded. TEST evaluations require evidence, MODEL_REVIEW evaluations require a finding, and neither action changes approval state.

Verified on 2026-09-26 with the project JDK 21: SkillWorkflowTest, EvaluationWorkflowTest and SkillParserTest pass all 8 tests. Core temporary-directory issues were fixed by supplying a project-local JVM temp directory; the broader core/workbench run also passed. Final combined HTTP/browser and packaging results are recorded separately, rather than treating these targeted tests as full application proof.

For Java review, trace import → parser → bundle hash → metadata first. Then review save and export separately. The service does not execute skill text or a model. Text bundles are capped at 128 files/directories and 256 KiB, with SKILL.md capped at 32 KiB; binary bundles are outside this first version. File-system atomic moves are required. This is not a database transaction across the bundle and metadata, and external programs can still race a final hash check.
